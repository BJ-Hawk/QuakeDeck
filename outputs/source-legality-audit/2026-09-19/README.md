# QuakeDeck data-use legality audit

Reviewed: **19 September 2026**.

This replaces the 2 September findings for data use. It audits what the current checkout actually does: where data enters, which fields are bundled, what is calculated, what is stored locally, and whether QuakeDeck sends it to anyone else. It does not treat the mere presence of a source name as prohibited use.

## Clear result

QuakeDeck does **not** operate a central data or forecasting service. P2PQuake and DM-D.S.S traffic goes directly to the Android client. Archives and diagnostics remain on the user's device unless the user explicitly exports a file.

The current uses resolve as follows:

- **Permitted as implemented:** JMA public reports, station catalogue, code tables, multilingual dictionary and GIS; P2PQuake; Natural Earth; Digital Agency Address Base Registry; GSI locality results; the identified CC BY 4.0 prefectural datasets; NICT public NTP within the implemented limit; Android Geocoder; and ML Kit on-device translation with the implemented Google attribution.
- **Permitted for the current private/nonprofit project:** Nager.Date holiday API. A commercial release requires active sponsorship.
- **Permitted as a user-account client:** DM-D.S.S reception, display, notification, local archive/replay and user-triggered diagnostic export. Each user authorizes their own account and subscription. QuakeDeck does not receive the data centrally or expose it through an API.
- **NIED station metadata: scoped review remains open; no breach established.** Displaying a station's factual address, facility or location is not by itself evidence of a licence breach. The earlier mandatory-removal finding is withdrawn. Actual use separates JMA map coordinates, researched addresses/facilities from several sources, and 790 imported station-list records (783 K-NET, 7 KiK-net). NIED's restrictive site notices remain relevant to the systematic imports, but their applicability to this factual extraction was not established. See the [source-to-field-to-display trace](nied-station-data-use.md).
- **Private only pending permission/licensing:** QuakeDeck's own point intensity, arrival-time and wave calculations. JMA expressly treats distributed software that receives forecast material and calculates point intensity or arrival time as earthquake-motion forecasting business. DM-D.S.S also says its data cannot be used for that business and normally cannot be used to obtain the JMA licence. The existing ignored FULL engine boundary is therefore the correct publication boundary.

## Station catalogue versus station-details overlay

These are different datasets and must stay different in credits and legal decisions.

**NIED follow-up evidence:** the [detailed assessment](nied-station-data-use.md#follow-up-evidence-for-the-specific-nied-allegation) now compares NIED's broad notices with its narrower network-data rule and the copyright/contract requirements. It also verifies that the current procurement PDF contains white text in the address cells corresponding to all 559 rows carrying the importer's note; ordinary rendering hides those detailed portions, while the importer extracts them. This is a documented provenance concern, not proof of illegality. See [verification counts](nied-pdf-evidence.json).

1. `jma_intensity_stations.json` contains **4,360 official JMA rows**. Current provider counts are 670 JMA, 800 NIED-operated and 2,890 local-government stations. JMA is the supplier of every row.
2. `outputs/station-name-audit/station_metadata_sources.json` is a separate research dataset. The current working copy has 4,360 records, 9,755 source references, 786 unique URLs and 476 hosts.
3. The build task copies selected research fields into `station_details.json`. Current source coverage includes 3,442 published addresses, 2,949 Japanese facility names, 162 English facility names and **790 NIED provider tuples: 783 K-NET and 7 KiK-net**. All 800 NIED-operated rows have addresses; 619 have Japanese facility fields. Those counts identify the operator, not the address supplier.
4. Runtime station cards display the researched address/facility and provider network/code when present. Maps use the base catalogue coordinates. Raw provider names/coordinates, research notes and status are loaded without further runtime consumers; provider coordinates and names do have offline research uses. Approved English names are displayed through a separate resource.
5. The existing generated details file matches all 800 NIED-operated records across all 12 emitted fields. It differs from the current research source on 11 other rows, so it is not a current full-source snapshot. No released APK was inspected or rebuilt in this correction; packaging statements describe the build recipe and the existing generated resource.

Both previous blanket conclusions were unsupported: QuakeDeck does use NIED-supplied metadata, but that does not establish that displaying factual station details violates a licence. **Source, field, transformation and distribution must be assessed together.** Row-level `sourceUrls` combine several research sources and cannot identify the supplier of every field. The [correction and reproducible evidence](nied-station-data-use.md) supersede the earlier instruction to remove all 790 tuples or obtain permission.

## Forecast boundary

The current tracked implementation contains contracts, result models and reflection-based loading only. The actual equations, travel-time interpolation, AVS30 use, local regional intensity estimates, selected-location arrival estimates, wavefronts, warning-end estimate and fallback alert scope live in ignored `LocalEewForecastEngine.kt`.

`python tools/check_public_forecast_boundary.py --scope worktree` passes. A public checkout therefore builds LITE when the private engine/resources are absent.

That filesystem boundary does not settle two separate publication facts:

- JMA's current FAQ expressly includes distributed PC/device software that receives JMA forecast material and calculates point intensity or arrival time. Publishing FULL requires JMA forecast-business clearance/licensing; private use confined to the developer's own household does not.
- The FULL engine currently accepts a DM-D.S.S event and calculates local intensity from it. DM-D.S.S says its data cannot be used for earthquake-motion forecasting business and that its service normally cannot be used to obtain the JMA licence. A future licensed FULL release therefore needs a separately authorized forecast-material source or written DM-D.S.S clearance.

## Required publication actions

1. **NIED station metadata review:** resolve the applicability of each supplying site's terms to the documented factual extractions and derived names. The confirmed technical facts are in the [field trace](nied-station-data-use.md); a legal or provider clarification should address those uses specifically. No source removal is authorized or required by this audit correction. Do not describe either a confirmed breach or blanket permission without further evidence.
2. **FULL forecast implementation:** keep the ignored engine and J-SHIS lookup private until JMA clearance/licensing. Do not use the ordinary DM-D.S.S user feed as the data source for a published local forecast engine without separate provider authorization.
3. **Git history:** before claiming that forecast inputs/code were never published, either clean the affected history or obtain permissions that cover it. No history rewrite was attempted here.
4. **Commercial release:** activate Nager.Holidays sponsorship or replace the API before monetization.

Everything else reviewed here is usable under the stated attribution, notice and request-rate conditions. The machine-readable decision list is in [data-source-register.json](data-source-register.json).
